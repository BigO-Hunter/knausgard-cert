# CERT_DESIGN — kernel-checked replacements for the 3 computation-axioms

Doctrine: **the search is untrusted; only its output must be checkable.** The good news is that
Knausgård's development already contains the certificate-consumer theorem. The bad news is a
measured cost wall. This document gives both, with arithmetic.

## 1. The consumer theorem already exists (verified in source)

`Distinct839/Local/Spot.lean`, verbatim:

> `theorem basicF_sound (f : ℕ → ℕ) (hf : TableSound f) (lo hi : Array ℕ)
>     (h : basicF f lo hi = true) : BoxOK lo hi`

`BoxOK lo hi` is the local inequality on that box; `localInequality_of_boxOK : BoxOK rootLo
rootHi → LocalInequality` is the top-level join. And `basicF` is kernel-evaluable — the twelve
spot theorems are `basicF_sound kTab kTab_sound _ _ (by decide +kernel)`, and `Spot.lean`
explicitly says the spot boxes "are not boxes of the branch and bound".

So the per-box certificate needs **no new soundness mathematics for the test itself**, and
`localInequality_of_chunks (tab) (hsound) depth n (hn : 0 < n) (hcheck : ∀ i < n, checkChunk …)`
is already general in `depth` and in the number of parts.

What is **not** already there (correction to a natural first-pass reading):

- `localInequality_of_check/_checkPar/_chunks` all speak about `searchBox`/`checkChunk`, i.e. about
  *his* recursion, not about an arbitrary leaf list. A certificate version needs a **glue lemma**
  `covers_sound : Covers ls rootLo rootHi = true → (∀ l ∈ ls, BoxOK l) → LocalInequality`
  (bisection induction, ~100–200 lines, mirrors `Search.lean`'s existing recursion). Bounded work,
  but it is new Lean, not reuse.
- `TableSound f` must be supplied for whatever accessor `f` we use; it is available for his
  `kTabArray` only.

## 2. The cost wall (the central audit finding)

Measured input, `Distinct839/Local/Spot.lean` verbatim:

> "The Lean kernel cannot evaluate it: the table has 209010 entries, each costing the kernel
> about 0.1 s, and kernel arrays are lists."

Per-leaf table reads. For a box of width `w` grid cells in each gap, edge `(i,j)` spans about
`(j−i)·w` cells; summed over all pairs this is `56·w` reads for n=7 and `84·w` for n=8
(Σ_{i<j}(j−i) = 56, resp. 84). Stage-0 leaves read no table at all (pressure test only); stage-1/2
leaves read their spans, and terminal boxes have `w = 1`.

Using his own accepted-leaf counts as a conservative certificate size:

| Axiom | leaves | reads/leaf | kernel reads | at 0.1 s/read |
|---|---|---|---|---|
| 1 Distinct839 | 3.02e7 | 56 | 1.7e9 | **≈ 5.4 years** |
| 2 Simple673 (κ\*) | 2.68e8 | 84 | 2.3e10 | **≈ 71 years** |
| 3 Line889 | 2.86e8 | 56 | 1.6e10 | **≈ 51 years** |

This is why he says the whole search "is out of reach for it in practice". It is not leaf *count*
alone (3e7 is only ~4× the ~1,500-file / 5,651-case precedent he cites); it is **0.1 s per table
entry**, which is a cost of Lean's kernel representation of the table (lists), not of his search.

Corollary — the naive plans do not work, and should be dropped now rather than after a month:

- "Replay his leaf cover with `decide +kernel` per leaf" — 5 to 71 years.
- "Shrink the cover by 10–100×" — buys one to two orders against a 10^4–10^6 shortfall.
- "Use `localInequality_of_chunks` with more parts" — the kernel evaluates the same total work.
- "Replay on nanoda" — same kernel semantics; no compiled evaluation to exploit.

## 3. The lever: make table access kernel-cheap, then everything fits

The only quantity that has to move is seconds-per-table-read, and it plausibly moves by ~10^5
(0.1 s → ~1e-6 s) by representing the table as a kernel-cheap structure (segmented literals /
balanced tree keyed on the cell index) instead of an `Array` the kernel walks as a list.

Because `basicF` takes `f : ℕ → ℕ` and every soundness theorem only consumes `TableSound f`, a
faster accessor **does not touch any of his mathematics** — the risk is confined to (a) defining
`f`, (b) deriving `TableSound f` from his `kTabArray_sound` (one extensional lemma over 209,010
/ 262,144 entries — cheap if `f` lookup is cheap), (c) an RMQ layer so each leaf reads
O(log span + boundary) instead of O(span), and (d) the glue lemma of §1.

Projected totals at 1e-6 s/read with the same leaves: axiom 1 ≈ 28 min, axiom 2 ≈ 6.3 h,
axiom 3 ≈ 4.4 h of kernel time. That is inside the envelope his own builds already occupy
(`Line889.Local.RunAll` 94–110 min; `SpotChecks` modules 10–12 GB each).

**So the audit's pivotal number is a measurement, not a theorem: the real kernel cost of one
table read under a candidate representation.** It is a one-day experiment and it gates the whole
programme.

## 4. Certificate shape (per axiom)

```
LEAF   := (lo : Array Nat, hi : Array Nat)          -- dyadic, H = 16384
CERT   := leaf array generated by an UNTRUSTED search (Python/C++, exact integer arithmetic,
          dual-implementation cross-check like his C++/Python reference pair)
CHECK, per leaf:  basicF_sound tableSound_f lo hi (by decide +kernel)     -- BoxOK lo hi
CHECK, once:      covers_sound cert rootLo rootHi (by decide)            -- cover/partition
JOIN:             localInequality_of_boxOK → LocalInequality → (his existing) → headline theorem
AXIOMS:           propext, Classical.choice, Quot.sound.  Nothing else.
```

Hash-pin the certificate array (SHA-256 manifest, mirroring his `CHECKSUMS.sha256`), and validate
the generator against his ground truth before trusting it: reproduce his 12 kernel-checked spot
boxes, reproduce his accepted/visited counters on a subtree, and diff the table entry-for-entry.

## 5. Route B, stated and not recommended first

A sharper *analytic* per-box test (certified higher-order majorant of `K²` over a box, no table
reads) would let leaves be large and table-free — the clean long-term answer, and the only one
that scales to a case count a human can read. It is new certified mathematics (months), it risks
not reproducing his constants without recomputing the certificate weights, and it is unnecessary
while Route A's arithmetic closes.

we spend them.

## 7. Venue reality (checked, and it constrains everything)

riemann.fail (`josusanmartin/riemann`) accepts **one UTF-8 Lean file of at most 2 MB**, three
fixed declarations generated from a submitted exact rational, exact statement equality against
the pinned `anthropics/zeta-23-lean` `ChallengeDeps`, Lean **and** nanoda replay, 3 admitted
uploads/day/account, Apache-2.0.

Two hard blockers for uploading *his* proof:

1. **The dependency patch.** His development requires `upstream_relax.patch` (14 files under
   `Zeta23/`: `b ≥ 1/2 → 1/8`, `a ≥ 1/2 → 1/4`) because his windows are non-monotone and scaled
   by 2/5. The site checks out the pinned tree and does not accept a patched dependency; the
   relaxed five propositions cannot be re-proved inside a 2 MB one-file helper budget.
2. **Certificate volume.** Even self-contained, a 3e7-leaf certificate cannot be inlined in 2 MB.

So the venue-appropriate artifact is **not** a leaderboard upload. It is: the audit note + the
machinery offered to `kristianmk/839` (MIT for the certificate dirs, Apache-2.0 for `lean/`), and
a riemann.fail entry only if a future certificate becomes a <2 MB self-contained file over
unpatched zeta23. Say this plainly rather than promising an upload.
